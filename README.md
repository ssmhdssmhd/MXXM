## 快速开始

### 环境要求

- PHP >= 7.4，需开启 `curl`、`openssl`、`mbstring`
- 在线更新额外需要 `ZipArchive`
- Apache（启用 `mod_rewrite`）或 Nginx
- 可选 MySQL（默认使用文件配置）

### 本地运行

```bash
cd MXXM
php -S localhost:8080
```

浏览器访问 `http://localhost:8080`

### 后台管理

- 地址：`/admin/`
- 默认账号：`admin`
- 默认密码：`admin`

> 登录后请立即修改密码，并在「系统设置」中配置站点信息。

## 官替算法

将官方平台地址替换为资源站地址，两套算法调用方式一致。

### 算法 1（mx1）— 数据库匹配

- 入口：`域名/mx1/?url=官方视频地址`
- 原理：数据库匹配官方 URL 与 CMS `vod_play_url`，再从 CMS API 取真实播放地址
- 后台：官替算法 → 算法1，可配置 CMS、播放器编码、分类、解析接口、数据表与数据库
- 修改算法目录后，保存时自动复制算法文件

### 算法 2（mx2）— 多线程搜索

- 入口：`域名/mx2/?url=官方视频地址`
- 支持腾讯、爱奇艺、优酷、芒果 TV、哔哩哔哩、PPTV、搜狐
- 流程：解析链接 → 映射表 → 页面抓取识别片名 → 多线程搜索资源站 → 提取 m3u8
- 配置保存于 `mx2/config/*.json`，提供独立资源站管理后台

## 脚本解析

借助 UserScript 的解析线路播放，支持多脚本共存，内置脚本源：

- [88lin/video_vip](https://github.com/88lin/video_vip)
- [whyyy-404/video_freevip](https://github.com/whyyy-404/video_freevip)

**后台管理**

- 入口：脚本解析 → 脚本设置 / 返回响应设置
- 卡片式脚本列表：启用状态、版本、线路数、源码文件、更新时间
- 支持添加、更新、删除、全部更新，线路按地址自动去重
- 导入 / 导出源码目录 `/MXJB/`，远程拉取失败时自动使用本地副本
- 操作日志实时显示，刷新后保留上次记录

**解析线路**

- 支持直连线路多行配置：站点地址 / 资源接口 / m3u8 播放器
- 直连线路按顺序自动尝试，前一条失败自动切换
- 自动更新默认开启，按间隔检查上游脚本并同步解析线路

**独立 PHP 接口**

- `1.php`：`域名/1.php?url=官方视频地址` 返回 kanju-api 的 m3u8 JSON
- JB 接口：后台「脚本解析 → 脚本设置 → 独立 PHP 接口」勾选 19 个数字接口后点击「同步代码」
  - 从仓库 `JB/<编号>.php` 同步到 `kanju/jb/<编号>.php`
  - 自动在根目录生成 `/<编号>.php` 入口，例如 `/1118.php?url=...`
  - 入口复用 `1.php` 的接口开关、固定/动态密钥与系统防火墙校验
  - 取消勾选后再次同步会移除对应入口
- 动态密钥：后台「扩展功能 → 动态密钥」可设置更换周期 0-24 小时（0 = 不自动更换，1 = 每小时，24 = 每天，默认 1 小时）
- 动态密钥 JSON：`/MXDTKEY.json` 返回顶层 `key`、`expires`、`expires_in`、`interval` 等字段；APP 启动或密钥失效时自动读取并替换 `/1.php` 的 `key` 参数
- JSON 接口与 `/1.php` 共用同一份临时密钥和轮换逻辑，同步执行系统防火墙并写入「动态密钥接口」调用日志；只返回临时密钥，不返回管理员固定密钥
- Apache 自动将 `/MXDTKEY.json` 转发到 `/MXDTKEY.php`；Nginx 等未配置伪静态的环境可直接使用 `/MXDTKEY.php`
- 运行时文件 `kanju/jb/`、根目录数字 PHP 均已在 `.gitignore` 中忽略，不污染仓库

## 动态密钥 JSON 接口

用于避免 APP 把会变化的访问密钥写死在安装包中。APP 在启动或密钥失效时请求一次 JSON 接口，拿到当前可用的临时密钥，再调用 `/1.php`。

### 接口地址

| 地址 | 说明 |
| --- | --- |
| `/MXDTKEY.json` | 推荐地址，Apache 通过根目录 `.htaccess` 转发到 `MXDTKEY.php` |
| `/MXDTKEY.php` | 通用地址，Nginx 等未配置伪静态的环境直接使用 |

### 返回示例

```json
{
  "code": 200,
  "msg": "success",
  "key": "A1b2C3d4E5f6G7h8I9",
  "expires": 1795393200,
  "expires_at": "2026-11-23 09:40:00",
  "expires_in": 3600,
  "interval": 1,
  "api": "/1.php",
  "usage": "/1.php?url=官方视频地址&key=A1b2C3d4E5f6G7h8I9",
  "server_time": 1795389600
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 业务状态码，`200` 表示成功 |
| `msg` | 结果说明 |
| `key` | 当前动态临时密钥（18 位字母数字） |
| `expires` | 到期时间戳（秒） |
| `expires_at` | 到期时间（`Y-m-d H:i:s`） |
| `expires_in` | 剩余有效秒数 |
| `interval` | 轮换周期（小时，`0` 表示不自动轮换） |
| `api` | 需要携带 Key 的业务接口 |
| `usage` | 完整调用示例 |
| `server_time` | 服务器当前时间戳 |

### APP 接入流程

1. APP 启动时 `GET /MXDTKEY.json`，读取返回 JSON 顶层的 `key`；
2. 拼接调用地址：`/1.php?url=官方视频地址&key=读取到的key`；
3. 业务接口返回 `403`（密钥已轮换）时，重新请求 JSON 获取新 Key 并重试一次；
4. 可结合 `expires_in` 在本地缓存 Key，快到期时再刷新，减少请求次数。

```javascript
// H5 / uni-app / Hybrid 通用示例
async function getDynamicKey() {
  const res = await fetch('/MXDTKEY.json', { cache: 'no-store' });
  const data = await res.json();
  if (data.code !== 200 || !data.key) throw new Error(data.msg || '获取密钥失败');
  return data.key;
}

// 调用解析接口，密钥失效时自动刷新重试
async function parseVideo(url, retry = true) {
  const key = await getDynamicKey();
  const res = await fetch(`/1.php?url=${encodeURIComponent(url)}&key=${encodeURIComponent(key)}`);
  const data = await res.json();
  if (data.code === 403 && retry) return parseVideo(url, false);
  return data;
}
```

```bash
# 命令行调试
curl -s https://你的域名/MXDTKEY.json
```

### 与 `/1.php` 的关系

- 与 `/1.php` 共用同一份密钥配置和轮换逻辑，两个接口拿到的临时密钥始终一致；
- 同步执行系统防火墙规则，命中规则的请求同样会被拦截；
- 每次调用写入「日志与调用 → 调用日志」，模块为「动态密钥接口」；
- **只返回动态临时密钥，绝不返回管理员固定密钥**；
- 后台「扩展功能 → 动态密钥 → 动态 JSON 接口」可一键停用，停用后该地址返回 `403`。

### 错误码

| code | 说明 |
| --- | --- |
| `200` | 成功，`key` 为当前可用临时密钥 |
| `403` | 独立接口已关闭 / 动态 JSON 接口已关闭 / 动态密钥未启用 |
| `500` | 密钥生成或保存失败 |
| `503` | 动态密钥尚未生成，稍后重试 |

> 该接口用于避免 APP 硬编码 Key，不等同于私密鉴权。若需限制调用来源，请配合后台防火墙使用。

## 轮训接口

`LX/` 目录为独立的轮训模块：按顺序请求多条解析线路，返回第一条成功解析出 `url` 的结果。线路全部在后台可视化设置，无需修改代码。

### 调用方式

```text
域名/LX/?url=官方视频地址
域名/LX/?url=官方视频地址&line=2
```

| 参数 | 说明 |
| --- | --- |
| `url` | 必填，官方视频播放页地址，建议 URL 编码 |
| `line` | 可选，指定线路序号；不传或 `0` 表示按后台配置自动轮询 |

成功时直接返回解析线路的原始 JSON（至少包含 `url`），「返回附加字段」会覆盖返回中的同名值；失败时返回带 `code` / `msg` / `errormsg` 的 JSON。

### 后台设置

- 入口：扩展功能 → 轮训接口
- 可设置启用开关、指定线路与线路列表，并输入视频地址直接测试
- 每条线路支持：
  - 请求类型：`GET 拼接`（把视频地址接在接口地址后）或 `POST 表单`
  - 接口地址：支持 `{url}` 占位符，会自动对视频地址做 URL 编码。调用本站 `1.php` 时填写 `https://你的域名/1.php?key=你的密钥&url={url}`
  - 超时（1-60 秒）、Referer
  - POST 表单参数（每行 `key=value`，`url` 自动填充）
  - 返回附加字段（每行 `key=value`，覆盖返回同名值）
- 保存后立即生效，配置写入 `LX/config.php`，已加入 `.gitignore`，在线更新不会覆盖

### Key 自动同步

当线路调用本站 `/1.php` 时，可以把访问密钥改成自动同步，避免动态密钥轮换后线路失效：

- 在后台「扩展功能 → 轮训接口」启用「Key 同步」
- 同步地址填写 `https://你的域名/MXDTKEY.json`（或 `/MXDTKEY.php`）
- 设置同步间隔（分钟，建议 5-30 分钟）
- 保存后点击「立即同步 Key」，系统会读取 JSON 顶层的 `key`，并自动替换线路接口地址中的 `key=旧值`
- 线路接口地址也可以直接写 `key={key}` 占位符，调用时自动替换为当前 Key
- 到达同步间隔后，`/LX/` 收到请求会自动重新获取 Key，无需人工操作；页面会显示当前 Key、上次同步时间与错误信息

示例线路地址：

```text
https://你的域名/1.php?key={key}&url={url}
```

### 常见问题

- **视频地址带 `&` 时解析失败**：说明线路还在用直接拼接，`&` 后面的参数被截断。请把接口地址改成 `...&url={url}`，`{url}` 会自动编码。
- **提示「上游返回：接口未授权」**：线路调用的 `1.php` 缺少 `key` 参数，请在接口地址中补上 `key=你的密钥`，例如 `https://你的域名/1.php?key=你的密钥&url={url}`。使用动态密钥时建议启用「Key 同步」，并写成 `key={key}`。
- **直接调用 `/1.php`**：视频地址必须 URL 编码，并且参数格式为 `?url=编码后的地址&key=密钥`；不要写成 `?&key=123&?url=...`，否则 `url` 会丢失。
- **全部线路失败**：返回的 `logs` 会列出每条线路的具体原因，可据此关闭失效线路或调整参数。

### 错误码

| code | 说明 |
| --- | --- |
| `200` | 解析成功，返回线路原始 JSON |
| `400` | 未传 `url` 或地址格式错误 |
| `403` | 轮训接口已在后台停用 |
| `502` | 全部线路均未解析出 `url` |

失败示例：

```json
{"code":502,"msg":"返回数据中没有 url","errormsg":"返回数据中没有 url","logs":[{"line":1,"ok":0,"msg":"返回数据中没有 url"}]}
```

> 每次调用写入「日志与调用 → 调用日志」，模块为「轮训接口」。

- 支持实时更新站点列表、一键解析详情、同步到云播资源列表

- 规则随在线更新一并同步

## 在线更新

- 入口：在线更新 → 版本管理
- 实时对比本地 `version.php` 与远程仓库版本
- 一键从 `codeload.github.com` 拉取最新代码
- 更新过程显示实时进度条：下载更新包、解压、覆盖文件分阶段显示百分比、当前阶段与已用时间
- 官替算法独立更新使用同一套进度条，更新期间无需猜测等待时间
- 自动跳过 `save/`，不影响用户配置
- 顶栏「清理缓存」可清理服务器与浏览器缓存

> 需服务器可访问 GitHub，并开启 `ZipArchive` 与根目录写权限。

## 日志与调用

后台「日志与调用」位于「脚本解析」与「在线更新」之间，分为调用日志与操作日志两个页面。

### 调用日志

- 统一记录独立 PHP 接口（`1.php` 与同步生成的 JB 数字接口）的每次请求与响应码
- 记录各模块调用：脚本解析接口、JSON 解析接口、解析线路、主解析 API、官替算法 1 / 2
- 汇总调用总数、成功数、失败数、成功率与平均耗时，并按模块统计使用情况
- 支持按时间范围、模块、状态、关键词筛选与分页查看
- 日志按天写入 `save/logs/call/YYYYMMDD.log`，默认保留 30 天

### 操作日志

- 记录后台登录成功 / 失败、退出登录，以及配置保存、在线更新、脚本同步等操作
- 包含操作类型、结果、账号、IP、响应信息
- 支持按时间范围、类型、状态、关键词筛选与分页查看
- 日志按天写入 `save/logs/op/YYYYMMDD.log`，默认保留 90 天

> 日志目录已在 `.gitignore` 中忽略，不随在线更新覆盖；顶栏「重置」菜单提供「清空调用日志」「清空操作日志」一键清理入口，两个日志页内也保留各自的清空按钮。

## 开发规范

- 版本号：`v.主.次.修`，百位进一（`v.0.0.99` → `v.0.1.0`）
- 每次更新同步修改 `version.php` 与 README 版本记录
- 版本文件命名：`项目名.版本号 时间戳`，例如 `MXXM.v.0.0.59 202611182013`
- 文件名使用 `.` 分隔，编译产物不得出现 `-`
- Logo / Favicon 统一使用 [MXLOGO](https://github.com/ssmhdssmhd/MXLOGO)
- 上传前审查代码，禁止提交本地污染代码与敏感凭据
